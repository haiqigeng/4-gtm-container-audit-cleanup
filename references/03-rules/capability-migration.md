# v1.13 Capability Migration Ledger

## Purpose

The v2 design preserves useful behaviour, not old run names, schemas, workbook
tabs, or compatibility paths. Each capability has one explicit disposition.

| Capability | Disposition | v2 proof surface |
| --- | --- | --- |
| Source, skill, and context identity | Strengthened | Source/package hashes, complete layer and ID gate, explicit supplied/inferred/empty context, exact `do_not_touch` keys |
| Deterministic evidence and completeness | Consolidated | One canonical scan, independent raw-source assurance, typed obligation ledger |
| Broken references, lifecycle, duplication, trigger, sequence, naming, folder, Zone, settings, consent, destination, client, transformation, and template defects | Retained and extended | Areas 1–26 plus detector and workflow fixtures |
| Custom code and template coverage | Strengthened | Stable object/segment/line/hash/parser identities and semantic obligations |
| Vendor and product contracts | Consolidated | One dated official-first registry; unmatched identities get one research owner |
| Approved external requirements | Adapted | Locked hashes, withheld until each source-only checkpoint, never merged into scan facts |
| Consent and client/server routing | Strengthened | Four-class route model, direct blocker rule, Advanced proof, pure transporter inheritance, unseen-server boundary |
| Business architecture and open discovery | Strengthened | Families, singletons, relationship candidates, candidate-independent discovery, greenfield target |
| Independent semantic review | Replaced | Two complete host-scoped audits plus targeted neutral verification |
| Sharding, sealing, and repair | Adapted | Family work units, shared-infrastructure unit, immutable seals, fresh-context append-only amendments |
| Target state and exact operations | Retained within phase | Creates/additions/changes/named-field removals/remaps/renames/pauses/deletions, dependency order, projection and replay |
| Decision calibration | Simplified | Decision class, analyst priority, and evidence confidence; no redundant severity score |
| Agent/runtime portability | Retained at artifact level | File contracts, hashes, validators, no model-private state dependency |
| Human delivery | Replaced and simplified | One canonical JSON record and one purpose-built analyst workbook |
| Row-level execution approval | Deliberately deferred | Absent from runtime |
| GTM/API/MCP mutation and import application | Deliberately deferred | Absent from runtime |
| Execution preflight, drift/readback certification | Deliberately deferred | Absent from runtime |
| Change logs and audit-to-audit delta | Deliberately deferred | Absent from runtime |
| Three complementary review runs and copied dual-workbook delivery | Obsolete implementation removed | No command, schema, validator, or compatibility mode remains |

## Regression Rule

Every retained, strengthened, or consolidated capability needs at least one
observable v2 assertion. Deferred capabilities pass only by being absent and
clearly out of scope. The ledger never requires old filenames, legacy schema
fields, or adapters.
